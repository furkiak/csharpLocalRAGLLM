Version `0.3.0-preview.3` targets Python 3.12, .NET 10 and local SQLite on Windows first. Default extraction remains model-free; generation is opt-in. CI declares Python/C# fixture checks on Ubuntu and Windows; remote CI results must be observed after pushing. Synthetic protocol tests and dated actual Qwen2.5-1.5B / llama.cpp CPU results are distinguished in [LOCAL_MODEL](LOCAL_MODEL.md). Schema-constrained format consistency does not establish factual or conflict-handling quality.

The new index uses `rag-v2.sqlite3` in the configured folder. It does not open, convert or delete older Chroma files (`chroma.sqlite3`, `chroma_db` or `documents_v1`). Preserve those files and re-ingest original TXT/MD/PDF documents with the same source IDs. This is a backend change; existing Chroma entries are not visible until re-ingested. Replacement and stale-chunk removal are one transaction; insert failure rolls it back. A small synthetic restart test preserves the old Chroma fixture byte-for-byte. To back up the SQLite demo, stop the API and copy the entire index directory; restore only with the compatible preview/environment and verify your source IDs. No real-user data migration or backup drill has been performed. The exact vector scan is O(n); the 10,000-chunk cap makes this a bounded demonstration, not a large-corpus vector service. Stop the server with Ctrl+C before changing environments. `.rag-data` is ignored by Git but stays on disk until its owner removes it.

[Local generation setup and EN/TR limits](LOCAL_MODEL.md) documents opt-in configuration, official reference sources and dated genuine-model observations. No model/runtime is included or automatically downloaded/started. Client cancellation stops its wait; cancellation of backend inference is not claimed. Real-model format results do not close the quality, fresh-machine, CI or public release gates.
